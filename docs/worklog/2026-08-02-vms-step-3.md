## Criterion

> *Admin CRUD, by city. Done when a camera can be added and tagged.*

`/api/VmsAdmin`, Administrator-only at the group level:

| | |
|---|---|
| `GET /cities` | the cities, each with its live camera count |
| `GET /` | cameras, optionally `?cityCode=` |
| `GET /{id}` · `POST /` · `PUT /{id}` | read, create, update |
| `POST /{id}/active` · `DELETE /{id}` | switch off, soft delete |

## Four decisions

### 1. The stream key is generated, never typed

`{city}-{nn}` — `baneh-01`, `baneh-02`. It is absent from `CameraInput` entirely.

It ends up in go2rtc's config, in its logs, and in the URL a browser asks for. A typo produces a
camera that silently never appears, and uniqueness is not something an admin can check from a form.

**It is never regenerated, not even when the camera moves city.** A camera moved from بانه to مریوان
keeps `baneh-01`, because the key is an identifier and not a label — go2rtc's config and every open
tab already use it, and renaming it to tidy a string would break a working stream.

**Deleted cameras keep their key reserved.** `NextStreamKey` is passed every key including
soft-deleted rows, so `baneh-01` never comes back. A recycled key would let a stale go2rtc entry, or
a tab somebody left open, show a different camera than the one it names.

### 2. Two rows may not point at one physical stream

Refused on create and update: same `Host` + `RtspPort` + `Channel`.

This is step 1's measurement turned into a rule. The site uploads ~0.41 Mbit/s and the substream
needs ~0.35, so there is room for exactly **one** puller. Two rows would have go2rtc open two
sessions and starve both — and the symptom is the camera appearing to drop out, which reads as a
fault at the site rather than as a duplicate row somebody typed months earlier.

The same host on a *different* channel is allowed: a four-channel recorder behind one address is a
real arrangement, and each channel is its own picture.

### 3. The city is checked in the handler even though the FK already checks it

The foreign key would refuse an unknown code anyway — as a `DbUpdateException` carrying a constraint
name, which reaches the admin as an unexplained 500. `EnsureCityAsync` turns it into «این شهر در
فهرست شهرها نیست», and it also catches a city that exists but has been **switched off**, which the
database has no opinion about.

### 4. Flat validation keys, deliberately, with a test

Both command validators use `.OverridePropertyName(string.Empty)`. Without it FluentValidation
answers `Input.Host` to a form whose field is `host`, and the panel shows "this failed" with nothing
highlighted. The room service shipped exactly that bug. `No_error_key_is_ever_dotted_on_create`
breaks every rule at once and asserts no key contains a dot, so the check covers the whole validator
rather than the fields a future edit happens to leave alone.

## Verification

- **Unit 359 passed** (+26). **Functional 176 passed / 3 failed** (+20).
- The 3 are the same pre-existing failures recorded in the step 2 worklog, confirmed there against a
  clean tree.
- **`VmsAdminRouteTests` is the one that matters most.** Everything else goes through MediatR, which
  never touches HTTP — precisely the blind spot that let a duplicate handler name reach production
  and make *every* route in the API answer 500 while the room tests stayed green. It asserts the
  seven mapped routes by name, and makes a real unauthenticated request expecting **401**, not 404
  and not 500. `EndpointNameTests` passes, so no handler name collides.
- Both collection routes map with a trailing slash (`GET /api/VmsAdmin/`) because the group maps them
  at `string.Empty`, the same as `RoomAdmin`. Both spellings match at request time — the 401 test asks
  for `/api/VmsAdmin` without the slash.

## Left for later, on purpose

- **`CredentialKey` is free text, validated as a lower-case slug.** It should be a picker over the
  keys that actually exist on the VPS, and it cannot be until step 4 knows what is in that file. A
  typo today produces a camera that fails to connect for a reason no message explains — so **step 4's
  generator must report any key the VPS does not have**, rather than writing a config that silently
  will not authenticate.
- No UI. `vms-web` is step 6.
- Still open from step 1, and it decides how much of this matters: **is ~0.41 Mbit/s typical of every
  site?** Two or three more camera IPs would settle it.
